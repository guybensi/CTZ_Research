--- Model logic (what each stage actually is) ---
guy_model_1.0.py is a two-stage classical-ML + deep-learning pipeline, all run on
the *same* fixed top-20 feature subset so the two model types are compared
head-to-head:
  1. Feature selection (classical ML, not a predictor itself): a Random
     Forest regressor (50 trees, max depth 10) is fit on standardized inputs
     purely to rank features by mean-decrease-in-impurity importance; the
     top 20 of 129 features are kept and the forest itself is discarded.
  2. Classical baseline: Ridge Regression - ordinary least squares with L2
     (weight-shrinkage) regularization, alpha=1.0. It assumes Fsw is
     approximately a linear combination of the 20 selected features; the
     regularization mainly controls coefficient variance from features that
     are correlated with each other (e.g. adjacent spectral moments).
     Output: a single continuous predicted Fsw value (W/m^2) per test row,
     from ridge.predict(X_test_scaled) - scored RMSE=11.03, MAE=8.38,
     R^2=0.9796 in the table above.
  3. Deep learning model: a feed-forward artificial neural network / MLP
     (Normalization layer -> Dense(10, ReLU) -> Dense(8, ReLU) -> Dense(1,
     linear)), trained with Adam + MSE loss and early stopping on validation
     loss (patience 15) to avoid overfitting the ~1.36M-row training set.
     Its job is to capture whatever non-linearity in Fsw ~ features remains
     after Ridge, on the exact same 20 features, so the R^2 gap between the
     two rows above (0.9796 -> 0.9944) is attributable to non-linearity
     rather than to a different feature set.

--- Pipeline input/output flow (per stage) ---
Stage 0 - Data loading (load_paired_moments_scalars):
  Input:  2163 moments+scalars NPZ file pairs
  Output: X (1,703,803 x 129 float32 feature matrix), y (1,703,803,) Fsw
          target (rows with any NaN/Inf across features+target dropped)

Stage 1 - Feature selection (Random Forest importance ranking):
  Input:  X (1,703,803 x 129), y (1,703,803,)
  Output: top_indices (20,) - column indices into X, ranked by
          mean-decrease-in-impurity importance from a 50-tree, max-depth-10
          RF fit on standardized inputs; the forest itself is discarded
          -> X_top = X[:, top_indices]  (1,703,803 x 20)

Stage 2 - Train/test split:
  Input:  X_top (1,703,803 x 20), y (1,703,803,)
  Output: X_train/y_train (~1,363,042 rows), X_test/y_test (~340,761 rows),
          80/20 split, random_state=42

Stage 3 - Classical baseline (Ridge, alpha=1.0):
  Input:  X_train/X_test standardized via a StandardScaler fit on X_train
          (20 features), y_train
  Output: ridge_pred (n_test,) predicted Fsw (W/m^2); metrics RMSE=11.03,
          MAE=8.38, R^2=0.9796; artifacts ridge_model.joblib,
          ridge_scaler.joblib

Stage 4 - ANN (Normalization -> Dense(10, ReLU) -> Dense(8, ReLU) ->
           Dense(1, linear)):
  Input:  X_train/X_test raw/unscaled (the Normalization layer learns
          feature scaling internally), y_train; Adam + MSE, early stopping
          on validation loss (patience 15), up to 150 epochs
  Output: ann_pred (n_test,) predicted Fsw (W/m^2); metrics RMSE=5.76,
          MAE=4.06, R^2=0.9944; artifact ann_model.keras

Stage 5 - Summary:
  Input:  top_indices, ridge_metrics, ann_metrics, X.shape
  Output: final_model_summary.json (feature indices + both models' metrics)

--- Model logic (what the script actually is) ---
All_Sky_AIflux.py is deep-learning-only regression; there is no automatic
feature-selection or classical-model-comparison step (the `linreg` flag can
switch in a plain linear-regression branch, but it defaults to 0/off, so only
the ANN branch runs):
  - Feature set is fixed and hand-designed from radiative-transfer domain
    knowledge (viewing geometry + spectral mean/skew at 17 chosen
    wavelengths), not learned or ranked from the data the way guy_model_1.0.py's
    Random Forest importance step is.
  - Architecture: a Keras functional-API MLP where each of the 37 features
    gets its own per-feature Normalization layer (rather than one joint
    normalization over the whole matrix), the normalized features are
    concatenated, then passed through up to 4 configurable Dense layers with
    ReLU activation and L1 kernel regularization (a weight-sparsity penalty:
    0.01 on the first hidden layer, 0.001 on deeper ones) - only the first
    layer (18 units, i.e. half of 37 features) is enabled by default, the
    other 3 are sized to 0 and skipped - ending in a single linear output
    neuron. Same Adam + MSE training setup as guy_model_1.0.py's ANN, but no
    early stopping: it always runs the full 200 epochs.
  - After training, it fits a separate scikit-learn LinearRegression between
    the ANN's raw predictions and the true test labels. This is a post-hoc
    bias/scale correction and diagnostic (for the R^2/plots), not a second
    trained model competing with the ANN.
  - Net effect: this script is a single-hidden-layer, hand-featured DL
    regressor with no train/test model-selection loop, versus guy_model_1.0.py's
    deeper (2-hidden-layer) DL regressor on RF-importance-selected features
    that is explicitly benchmarked against a Ridge linear baseline.

================================================================================
4. COMPARISON: guy_model_1.0.py vs. guy_model_2.0.py vs. All_Sky_AIflux.py
================================================================================
All three run on the same 2163 moments+scalars NPZ pairs from
data/paired/Pacific_2014-2015 (target Fsw, W/m^2), but on different feature
pools/row filters - see sections 1-3 above for each one's full data/model
details. Summary:

Model                                    | RMSE (W/m^2) | MAE (W/m^2) | R^2
------------------------------------------------------------------------------
guy_model_1.0.py Ridge (top-20 of 129)   |    11.03     |    8.38     | 0.9796
guy_model_1.0.py ANN   (top-20 of 129)   |     5.76     |    4.06     | 0.9944
guy_model_2.0.py Ridge (--feature-source
  allsky37, all 37)                      |    22.27     |    16.40    | 0.9805
guy_model_2.0.py ANN   (--feature-source
  allsky37, all 37)                      |    15.33     |    10.79    | 0.9907
All_Sky_AIflux.py ANN (37 hand-picked)   |    17.72     | not printed | not printed
                                                          (~0.97, see section 2)

- guy_model_1.0.py's ANN (RMSE=5.76) is the clear winner overall - roughly 3x
  lower error than All_Sky_AIflux.py's ANN (17.72) and guy_model_2.0.py's
  allsky37 ANN (15.33). Its Ridge baseline alone (11.03) already beats both
  of the other scripts' ANNs.
- guy_model_2.0.py's allsky37 mode isolates the architecture/training-setup
  effect from the feature-set effect: restricted to (almost) the same 37
  hand-picked features as All_Sky_AIflux.py, its ANN still beats
  All_Sky_AIflux.py's ANN (15.33 vs 17.72, ~14% lower RMSE) - guy_model's two
  hidden layers (18, 9 units) with early stopping generalize a bit better
  than All_Sky_AIflux.py's single 18-unit layer trained for a fixed 200
  epochs, but the gap here is modest compared to guy_model_1.0.py's lead
  below.
- Contrast that ~14% architecture-only gap against guy_model_1.0.py's ~3x
  advantage over both 37-feature runs: the dominant contributor to
  guy_model_1.0.py's overall lead is feature-set breadth (Isw/Ilw radiance,
  AOD/Clrf/CF/CTH cloud-aerosol scalars, Lat/Lon - 129 candidate features
  vs. 37), not architecture. Losing that pool (guy_model_2.0.py's allsky37
  mode) costs roughly as much accuracy as switching away from guy_model
  entirely to All_Sky_AIflux.py's simpler network.
- Other differences that keep this from being a fully controlled experiment:
  train/test split (80/20 for both guy_model versions vs. 70/30 for
  All_Sky_AIflux.py); row counts/filters differ (1,703,803 all-finite rows
  for guy_model_1.0.py vs. 5,260,208 for guy_model_2.0.py's allsky37 mode vs.
  2,909,419 cloud-height-filtered rows for All_Sky_AIflux.py - same
  underlying 2163 NPZ pairs, different row-level filtering per script). All
  three scripts were run with their original regression logic intact (per
  project rules), so this reflects the existing pipelines as-is, not a
  tuned apples-to-apples experiment.
