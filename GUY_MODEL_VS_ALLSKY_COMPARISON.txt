--- Model logic (what each stage actually is) ---
guy_model.py is a two-stage classical-ML + deep-learning pipeline, all run on
the *same* fixed top-20 feature subset so the two model types are compared
head-to-head:
  1. Feature selection (classical ML, not a predictor itself): a Random
     Forest regressor (50 trees, max depth 10) is fit on standardized inputs
     purely to rank features by mean-decrease-in-impurity importance; the
     top 20 of 129 features are kept and the forest itself is discarded.
  2. Classical baseline: Ridge Regression - ordinary least squares with L2
     (weight-shrinkage) regularization, alpha=1.0. It assumes Fsw is
     approximately a linear combination of the 20 selected features; the
     regularization mainly controls coefficient variance from features that
     are correlated with each other (e.g. adjacent spectral moments).
     Output: a single continuous predicted Fsw value (W/m^2) per test row,
     from ridge.predict(X_test_scaled) - scored RMSE=11.03, MAE=8.38,
     R^2=0.9796 in the table above.
  3. Deep learning model: a feed-forward artificial neural network / MLP
     (Normalization layer -> Dense(10, ReLU) -> Dense(8, ReLU) -> Dense(1,
     linear)), trained with Adam + MSE loss and early stopping on validation
     loss (patience 15) to avoid overfitting the ~1.36M-row training set.
     Its job is to capture whatever non-linearity in Fsw ~ features remains
     after Ridge, on the exact same 20 features, so the R^2 gap between the
     two rows above (0.9796 -> 0.9944) is attributable to non-linearity
     rather than to a different feature set.

--- Pipeline input/output flow (per stage) ---
Stage 0 - Data loading (load_paired_moments_scalars):
  Input:  2163 moments+scalars NPZ file pairs
  Output: X (1,703,803 x 129 float32 feature matrix), y (1,703,803,) Fsw
          target (rows with any NaN/Inf across features+target dropped)

Stage 1 - Feature selection (Random Forest importance ranking):
  Input:  X (1,703,803 x 129), y (1,703,803,)
  Output: top_indices (20,) - column indices into X, ranked by
          mean-decrease-in-impurity importance from a 50-tree, max-depth-10
          RF fit on standardized inputs; the forest itself is discarded
          -> X_top = X[:, top_indices]  (1,703,803 x 20)

Stage 2 - Train/test split:
  Input:  X_top (1,703,803 x 20), y (1,703,803,)
  Output: X_train/y_train (~1,363,042 rows), X_test/y_test (~340,761 rows),
          80/20 split, random_state=42

Stage 3 - Classical baseline (Ridge, alpha=1.0):
  Input:  X_train/X_test standardized via a StandardScaler fit on X_train
          (20 features), y_train
  Output: ridge_pred (n_test,) predicted Fsw (W/m^2); metrics RMSE=11.03,
          MAE=8.38, R^2=0.9796; artifacts ridge_model.joblib,
          ridge_scaler.joblib

Stage 4 - ANN (Normalization -> Dense(10, ReLU) -> Dense(8, ReLU) ->
           Dense(1, linear)):
  Input:  X_train/X_test raw/unscaled (the Normalization layer learns
          feature scaling internally), y_train; Adam + MSE, early stopping
          on validation loss (patience 15), up to 150 epochs
  Output: ann_pred (n_test,) predicted Fsw (W/m^2); metrics RMSE=5.76,
          MAE=4.06, R^2=0.9944; artifact ann_model.keras

Stage 5 - Summary:
  Input:  top_indices, ridge_metrics, ann_metrics, X.shape
  Output: final_model_summary.json (feature indices + both models' metrics)

--- Model logic (what the script actually is) ---
All_Sky_AIflux.py is deep-learning-only regression; there is no automatic
feature-selection or classical-model-comparison step (the `linreg` flag can
switch in a plain linear-regression branch, but it defaults to 0/off, so only
the ANN branch runs):
  - Feature set is fixed and hand-designed from radiative-transfer domain
    knowledge (viewing geometry + spectral mean/skew at 17 chosen
    wavelengths), not learned or ranked from the data the way guy_model.py's
    Random Forest importance step is.
  - Architecture: a Keras functional-API MLP where each of the 37 features
    gets its own per-feature Normalization layer (rather than one joint
    normalization over the whole matrix), the normalized features are
    concatenated, then passed through up to 4 configurable Dense layers with
    ReLU activation and L1 kernel regularization (a weight-sparsity penalty:
    0.01 on the first hidden layer, 0.001 on deeper ones) - only the first
    layer (18 units, i.e. half of 37 features) is enabled by default, the
    other 3 are sized to 0 and skipped - ending in a single linear output
    neuron. Same Adam + MSE training setup as guy_model.py's ANN, but no
    early stopping: it always runs the full 200 epochs.
  - After training, it fits a separate scikit-learn LinearRegression between
    the ANN's raw predictions and the true test labels. This is a post-hoc
    bias/scale correction and diagnostic (for the R^2/plots), not a second
    trained model competing with the ANN.
  - Net effect: this script is a single-hidden-layer, hand-featured DL
    regressor with no train/test model-selection loop, versus guy_model.py's
    deeper (2-hidden-layer) DL regressor on RF-importance-selected features
    that is explicitly benchmarked against a Ridge linear baseline.

================================================================================
3. COMPARISON
================================================================================
- guy_model.py's ANN (RMSE=5.76 W/m^2) outperforms All_Sky_AIflux.py's ANN
  (RMSE=17.72 W/m^2) by roughly 3x lower error.
- guy_model.py's classical Ridge baseline alone (RMSE=11.03 W/m^2) also beats
  All_Sky_AIflux.py's ANN.
- Likely contributors to the gap:
  1. Feature selection: guy_model.py uses 20 features chosen by Random Forest
     importance ranking out of the full 129-feature moments+scalars set (includes
     cloud fraction, cloud top height, AOD, lat/lon, etc.). All_Sky_AIflux.py
     uses a fixed, smaller, hand-picked 37-feature set of geometry + spectral
     mean/skew only, with no cloud/aerosol/geolocation scalars.
  2. Network capacity: guy_model.py's ANN has two hidden layers (10, 8 units)
     vs. All_Sky_AIflux.py's single hidden layer (18 units).
  3. Train/test split: 80/20 vs 70/30.
  4. Sample counts differ too: guy_model.py trains/tests on 1,703,803 rows
     (all-finite rows only, no cloud filter), while All_Sky_AIflux.py
     trains/tests on 2,909,419 rows (cloud-height filtered, NaNs not
     explicitly dropped) - the two scripts are not evaluated on identical
     row sets, only the same underlying 2163 NPZ file pairs.
- Both scripts were run unmodified (original regression logic preserved per
  project rules); this comparison reflects the existing pipelines as-is, not a
  tuned apples-to-apples experiment.

scored against different row sets with different label variance (5.26M rows

important feature in the full 129-feature recipe) plus AOD/Clrf/Lat; within
the restricted 37-feature pool, a single channel (mean SW reflectance at
0.66um) ends up carrying ~93% of the RF importance on its own, well beyond
its role in the full recipe, since it has to substitute for information the
excluded scalars would otherwise provide.

6. IDEAS TO IMPROVE guy_model WHEN RESTRICTED TO THE 37 ALLSKY FEATURES
================================================================================
Date: 2026-08-02
Context: sections 4/5 showed that, restricted to SZA/VZA/RAA + mean/skew
spectra at the 17 All_Sky wavelengths (no Isw/Ilw/AOD/Clrf/CF/CTH/Lat/Lon),
Ridge RMSE roughly doubles (11.03 -> 22.27) and ANN RMSE roughly triples
(5.76 -> 15.33) versus the full 129-feature recipe. Ideas below are ranked
by expected effort-to-payoff, grounded either in what our own RF importance
ranking showed (section 4) or in the methodology of the attached AGU Advances
paper (Eytan et al. 2025, "The Net Radiative Effect of the Ill-Defined
Clear-Sky in the Vicinity of Clouds").

A. Drop Ridge, keep only the ANN (cheap, no new data/features needed)
   Ridge lost to the ANN in every single comparison run so far (full recipe:
   11.03 vs 5.76 RMSE; allsky37: 22.27 vs 15.33 RMSE) - it never wins, so it
   is not doing useful work as a "baseline" beyond a sanity check. Worse,
   select_best_practical_model() picks the practical feature-subset size
   using Ridge's R^2 (see section 4's top_20-vs-top_37 discrepancy) even
   though the ANN is what actually ships - a linear model's feature
   preference isn't necessarily the nonlinear model's preference. Fix: for
   the allsky37 recipe, either (a) skip Ridge entirely in guy_model.py and
   just report the ANN, or (b) change guys_benchmark_models.py's combo
   selection to rank combos by a quick ANN CV score instead of Ridge's.

B. Replace Ridge with a nonlinear classical baseline (cheap - already wired)
   guys_benchmark_models.py already supports Gradient Boosting/XGBoost/
   CatBoost/Random Forest via get_classical_models(); only Ridge+SVM are
   enabled in --feature-selection importance mode. Flux is not expected to
   be linear in radiance or in viewing/solar angles (the paper's anisotropic
   factor R that converts radiance to flux is itself angle- and
   optical-thickness-dependent - see Equations 10-14 and Figure 5 of the
   attached paper), so a tree-based model should fit the same 37 features
   better than Ridge without needing new data. Test with the flag already
   added to guys_benchmark_models.py:
     --importance-models "Ridge,Gradient Boosting,XGBoost"
   (drop SVM as before - doesn't scale to millions of rows; Gradient
   Boosting/XGBoost with modest n_estimators/max_depth should still run in
   reasonable time on ~4M rows, unlike SVR).

C. Reconstruct an Isw-like broadband-radiance feature from the spectrum
   (grounded directly in the paper's own method; moderate effort)
   In the full 129-feature recipe, Isw (SW radiance/irradiance) was the #2
   most important feature (section 1) - guy_model loses direct access to it
   under allsky37. But the attached paper's Equation 10-11 show broadband
   flux is approximated as a linear combination of a handful of narrow-band
   radiances: f = (pi/R) * sum(I_ch * alpha_ch), with alpha_ch regression
   coefficients from Loeb & Manalo-Smith (2005). We already have the
   per-channel mean spectra (mSWspec/mLWspec) for all 27 wavelengths, i.e.
   more raw material than the 37-feature pool currently exposes. Engineer an
   explicit "reconstructed Isw" feature (e.g. a fixed or fitted weighted sum
   of the SW channels) and add it alongside the 37 - this hands the model a
   physically-motivated proxy for the single scalar it's missing, without
   needing new data.

D. Cross-feature the spectrum against baseline channels (grounded in the
   paper's Appendix A(e); cheap, reuses existing data)
   The paper found that normalizing each wavelength by a baseline channel
   per spectral region (0.47um for SW/atmospheric background, 4.05um for
   mid-IR, 11.0um for the LW atmospheric window) measurably improved their
   own ANN's Fclr retrieval. Our RF ranking (section 4) found a single raw
   channel (m0.66) carrying ~93% of importance, which smells like the model
   using one channel as an implicit brightness proxy rather than the ratios
   the paper's domain experts found more informative - explicit
   ratio/cross-features (m_ch / m_baseline) are a direct, low-cost way to
   give the model that same signal in a more learnable form.

E. Swap skew moments for std moments (near-zero cost - same data, no new
   features)
   Section 4's RF ranking found every skew_* column at/near-zero importance
   (only sk9.7 and sk4.5 barely entered the top 20) - skew is essentially
   dead weight in the current 37-feature pool. The paper's own CTZ detection
   metric psi (Equation 16) is fundamentally a variance-normalized deviation
   from the clear-sky spectral signal - i.e. within-footprint standard
   deviation is exactly what the paper uses to flag cloud-contaminated
   "clear" pixels. Since CTZ contamination is a very plausible source of our
   largest prediction errors, swapping the 17 skew_* columns for the
   corresponding 17 std_* columns (already available in the same moments
   NPZ files, no new data needed) is a nearly-free experiment worth trying
   before anything that requires new features or data.

F. Angular/geometric feature engineering (cheap, same data)
   Ridge sees SZA/VZA/RAA as raw degrees; the paper's radiative-transfer
   argument (Section 2.1, Figure 5) is that the geometry enters through a
   markedly nonlinear anisotropic factor R (varies from <1 to >3 across the
   observed angle range, see Figure 5b). Adding cos(SZA), cos(VZA), sin/cos
   of RAA, and a VZA*RAA (or SZA*VZA) interaction term as explicit features
   would give a linear model (Ridge, or the reconstructed-Isw feature in C)
   a much easier time approximating R's nonlinearity; likely lower-value for
   the ANN, which can already learn such interactions from raw angles given
   enough data.

G. Stacked/residual model, only if A-F plateau (higher effort, likely not
   worth it given Ridge already loses outright - listed for completeness)
   Train Ridge (or the engineered-feature linear model from C/D/F) first,
   then train the ANN to predict the residual (true - Ridge prediction)
   rather than the raw target. This can occasionally squeeze out a bit more
   accuracy over a single end-to-end ANN, but given Ridge's R^2 is already
   dominated by the ANN's, the likely gain here is smaller than A-F above.

Suggested order to try, cheapest/most-grounded first: A -> E -> B -> D/F -> C
-> G. A and E cost nothing beyond a script change and can be tried
immediately with the existing Pacific_2014-2015 data; B just changes the
--importance-models flag already added to guys_benchmark_models.py; C/D/F
need small additions to load_allsky37_subset(); G is a bigger structural
change and probably premature.
